# Narraverse Orchestrator

这是 Narraverse2.0 的多 AI 协作指挥仓库。

## 这个仓库做什么

这里不保存 Narraverse2.0 的正式源代码，而只保存：

- 架构研究与决策；
- 任务拆分；
- AI 交接记录；
- 验收标准；
- 当前进度；
- 给不同 AI 的执行提示词。

正式代码仍然只在 `llys-p/Narraverse2.0` 中修改。

## 当前协作原则

1. **Workbuddy 是主力执行者**：额度较多，优先承担仓库调查、代码阅读、普通实现、测试、整理和交接。
2. **Codex 是稀缺高价值执行者**：额度较少，只处理复杂实现、核心重构、难排故障和高风险改动。
3. **豆包是稀缺辅助研究者**：额度较少，只在重大架构决策、方案复核或需要第二意见时使用。
4. 不让多个 AI 同时修改同一组文件。
5. 每次执行必须有明确任务文件；任务结束必须产生 HANDOFF。
6. 如果需要用户参与，必须明确告诉用户“下一段内容发给谁、让它做什么、做完带回什么”，不要让用户自己判断工作流。

## 当前最高目标

Narraverse2.0 不再围绕“模块三、模块四分别怎么修”来思考，而是重新规划完整链路：

`外部资料 → 整理/翻译/去重 → 总资料库 → 具体世界资料库 → 写作 / 世界运行 → 状态与事实 → 审核/采纳/回写`

其中重点研究：现有“游戏模式、叙界文字冒险、自由沙盒”是否应合并为一个统一互动运行时，由不同预设控制玩法。

## 目录

- `AGENTS.md`：所有 AI 必须遵守的协作规则。
- `docs/MASTER_PLAN.md`：当前总体研究与重构目标。
- `docs/CURRENT_STATE.md`：当前已知状态与待确认事项。
- `docs/AI_COLLAB.md`：多 AI 分工与交接规则。
- `docs/tasks/`：正式任务单。
- `docs/handoffs/`：任务交接记录。
- `docs/templates/`：任务与交接模板。
- `prompts/`：给 Workbuddy、Codex、豆包的启动提示词。
