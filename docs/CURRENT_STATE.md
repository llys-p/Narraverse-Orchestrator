# 当前状态

更新时间：2026-09-07

## 已知产品现状

Narraverse2.0 当前已经拥有多块有价值能力，但它们并没有完全收口到同一套数据和运行逻辑中。

当前重点包括：
- 总资料库 / Master Library；
- 角色与设定资料；
- 写作能力；
- 游戏模式；
- 叙界；
- 叙界内文字冒险；
- Module4 / 自由沙盒；
- 本地翻译与 8097 Bridge；
- 模型网关与多模型接入；
- Agent 体系。

## 当前最重要的问题

不是“模块数量太多”本身，而是要确认：
- 同一种角色/世界信息是否被多套系统重复表示；
- 游戏模式、文字冒险、自由沙盒是否各自维护运行状态；
- 三套玩法是否重复实现导演、状态、事件、行动判断等能力；
- 写作与互动运行时是否真正读取同一套世界资料；
- 总资料库与具体世界资料库之间的数据继承和版本关系是否足够清晰。

## 已知叙界嵌入问题

叙界当前通过持久 iframe 嵌入 Denova。现有桥接主要同步主题、语言、可见性和 Module4 打开/关闭等有限信息。

这不代表 iframe 必须马上删除，但说明当前“看起来在一起”和“真正共享同一上下文”不是一回事。

## Module4 当前理解

Module4 已经包含较完整的世界运行/模拟流程，例如预演、行动、相遇、判断、事实、日志、日结等。

现阶段需要重点确认这些能力是否应该下沉到统一互动运行时，而不是继续作为独立玩法系统存在。

## 当前决策

暂时不选择“继续补旧架构”或“全部重写”。

先做 SYSTEM MAP，再比较：
- A 渐进整合；
- B 保留资产、重构核心；
- C 近乎重写。
